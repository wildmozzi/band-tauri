# 지연 측정 절차 (P1-1)

GOAL 1절 지연 지표를 **숫자로** 확인하는 절차다. 도구는 두 가지다.

| 도구 | 어디서 | 무엇을 재나 | GOAL 1절 지표 |
|---|---|---|---|
| 하드웨어 루프백 | 오디오 설정 → **지연 측정** | 인터페이스 출력 → 입력 왕복(아날로그 입력 → 아날로그 출력, 소프트웨어 패스스루 기준) | 로컬 처리 지연(`estLatencyMs`) 검증·보정 |
| 에코 피어 | 합주실 → 연주자 행의 **📏** | 네트워크 포함 왕복(클릭 → 상대 → 나) | 입→귀 총 지연, 지터 버퍼 |

엔진 동작과 계산식은 [native-engine-design.md](overhaul/native-engine-design.md) 4절 "지연 측정"에 있다.

## 1. 준비물 (Focusrite Scarlett Solo 4세대 기준)

- Scarlett Solo 4th Gen, USB-C 케이블, Focusrite 드라이버(ASIO 포함)와 **Focusrite Control 2**
- 루프백 케이블 1개: 6.35mm(1/4") 잭 ↔ 6.35mm 잭(TRS 또는 TS)
- ASIO를 쓰려면 `asio` 피처로 빌드한 앱(`npm run dev:tauri` 전에 `CPAL_ASIO_DIR`, 또는 ASIO 포함 릴리스 빌드)

Solo 4세대 단자: 앞면 **입력 1**(XLR 마이크), **입력 2**(6.35mm 악기/라인), 헤드폰. 뒷면 **Line Output L/R**(6.35mm TRS), USB-C.

## 2. 인터페이스 설정 (Focusrite Control 2)

화면 이름은 Focusrite Control 2 버전에 따라 조금 다를 수 있다.

1. **샘플레이트 48kHz**: Focusrite Control 2 설정(또는 ASIO 제어판)에서 48kHz로 맞춘다. 앱 내부 레이트가 48kHz라서 리샘플이 없다.
2. **직접 모니터(Direct Monitor) 끄기**: 앞면 Direct Monitor 버튼 또는 Focusrite Control 2에서 끈다. **켜 두면 입력이 하드웨어에서 바로 출력으로 섞여 루프백 결과가 0ms 근처로 틀어지거나 "불안정"이 된다.**
3. **입력 2**: INST(악기) 끄기 = 라인 레벨. Air 끄기. 게인 노브는 **최소**에서 시작한다.
4. 48V(팬텀)는 끈다(입력 1을 쓰지 않으므로 상관없지만 안전하게).
5. 출력(Monitor) 볼륨은 중간(12시)에서 시작한다.

## 3. 케이블 연결

- **권장**: 뒷면 **Line Output L** → 앞면 **입력 2**(6.35mm).
- 대안: 헤드폰 출력 → 입력 2. 헤드폰 볼륨은 낮게 둔다.
- 케이블이 없으면 스피커 앞 10cm에 마이크를 두고 입력 1(XLR)로 받아도 된다. 이 경우 공기 중 전파 지연(약 0.3ms/10cm)이 더해지고, 주변을 조용히 해야 한다.

앱의 **입력 채널**을 연결한 단자로 맞춘다: 입력 2면 오디오 설정 → 입력 → **Ch2**(모노). 루프백 측정은 라우팅된 **첫 번째** 입력 채널을 녹음한다.

## 4. 하드웨어 루프백 측정

1. 앱 → 오디오 설정: 입력/출력 드라이버 **ASIO**, 장치 **Focusrite USB ASIO**, 프레임 2.5ms(프리셋 "초저지연"이면 자동), 버퍼를 아래 표 순서로 바꾼다.
2. **지연 측정** 패널 → 반복 8회 → **측정 실행**. 테스트 엔진이 꺼져 있으면 자동으로 켠다. 출력에서 짧은 "삑" 소리가 8번 난다(약 6초).
3. 판정 확인:
   - **정상**: 값을 기록한다.
   - **신호 미검출**: 케이블, 입력 채널(Ch2), 게인을 확인한다. 게인을 조금 올린다.
   - **클리핑**: 게인 또는 출력 볼륨을 내린다(Focusrite 게인 링이 빨간색이면 과다).
   - **불안정**: 직접 모니터가 꺼졌는지, 주변 소음이 없는지 확인하고 다시 잰다.
4. **결과 복사** 또는 **텍스트로 저장**으로 결과를 남긴다. 텍스트 끝의 "백로그 기록" 줄을 그대로 BACKLOG에 붙인다(6절).
5. 버퍼 32 / 64 / 128에서 각각 잰다. WASAPI 독점(내장 장치 또는 Focusrite WASAPI)도 한 번 잰다.

| 버퍼(48kHz) | 장치 버퍼 왕복(입력 + 출력) | 프레임 2.5ms일 때 `estLatencyMs` |
|---|---|---|
| 32 | 1.33ms | 3.83ms |
| 64 | 2.67ms | 5.17ms |
| 128 | 5.33ms | 7.83ms |

GOAL 1절 목표: 로컬 처리 지연 ASIO 128샘플/2.5ms 프레임 ≤ 8ms, WASAPI 독점 ≤ 15ms.

결과 표 읽는 법:
- **실측 왕복**: 출력 → 입력 왕복의 중앙값. 이상적인 장치에서 입력 버퍼 + 출력 버퍼 + 변환기·드라이버 안전 여유다.
- **드라이버 보고 왕복**: ASIO `ASIOGetLatencies` 입력 + 출력. **드라이버 보고 오차**가 크면(±1ms 이상) 드라이버가 안전 여유를 덜 보고하는 것이다.
- **보정값**: 실측 − 장치 버퍼 왕복. `estLatencyMs`에 없는 숨은 지연이다. 입→귀 지연을 계산할 때 입력 몫과 출력 몫을 반씩 더한다고 보면 된다.
- **보정한 로컬 지연**: `estLatencyMs` + 보정값. GOAL 1절 "로컬 처리 지연 ≤ 8ms"와 비교할 때는 `estLatencyMs`(엔진 정의)와 이 값을 함께 적는다.

## 5. 에코 피어 측정 (네트워크 포함 왕복)

두 PC(A = 측정하는 쪽, B = 에코하는 쪽)가 같은 방에서 연주 중이어야 한다.

1. A: 합주실 연주자 목록에서 B 행의 **📏** → **측정 시작**.
2. B: 자기 화면의 A 행에 "에코 측정을 요청했습니다"가 뜨면 **허용**. (30초 안에 허용하지 않으면 A의 측정은 "수락하지 않았습니다"로 끝난다.)
3. 측정은 약 4초 걸린다. 그동안 B에게는 A의 소리 대신 클릭이 가고 A는 되돌아온 클릭을 듣는다. 다른 연주자에게는 평소 소리가 간다.
4. 끝나면 B의 에코는 자동으로 멈춘다(B 화면의 "응답 중" 표시가 사라진다).
5. A: 결과를 복사/저장한다. 같은 회선에서 3번 재서 중앙값을 적는다. 가능하면 같은 도시(RTT ≤ 10ms)와 원거리(RTT ≤ 30ms) 각각 잰다.

결과 표 읽는 법:
- **네트워크 포함 왕복** = 프레임 + 망 왕복 + 상대 되돌리기 + 내 지터 버퍼.
- **편도 추정** = (왕복 − 상대 처리 지연) / 2.
- **입→귀 추정** = 입력 버퍼 + 프레임 + 망 편도 + 지터 버퍼 + 출력 버퍼(상대도 나와 같은 설정이라고 가정). GOAL 1절 "같은 도시 ≤ 25ms, 원거리 ≤ 40ms"와 비교한다. 4절의 보정값이 있으면 더해서 적는다.
- **판정**의 클릭 수 옆 "튄 값 1개 제외"는 한 번만 크게 튄 클릭을 통계에서 뺐다는 뜻이다(텍스트의 클릭 목록에 "(튄 값, 통계 제외)"로 표시). 하나만 빼므로 둘 이상 튀거나 전체가 넓게 흩어지면(남은 값의 최대 − 최소 > 5ms) "불안정"이 된다. 기준은 설계 문서 4절 "지연 측정" 에코 판정.
- **잔차**는 통계로 설명되지 않는 몫이다. 클릭이 놓인 입력 버스트 위상만큼(≤ 입력 버퍼) 흩어지는 것은 정상이다. 5ms를 넘으면 숨은 지연을 의심한다.

## 6. BACKLOG 기록 형식

결과 텍스트의 "백로그 기록" 줄을 해당 항목 아래에 붙인다(작업자는 PR/보고에 적고, BACKLOG 파일은 코디네이터가 고친다).

```
[실측 YYYY-MM-DD] 루프백 <장치·드라이버·버퍼·프레임> <레이트>Hz/<입력 버퍼>: 왕복 Xms(σ Sms), 드라이버 보고 Yms, est Zms, 보정 +Wms — <판정>
[실측 YYYY-MM-DD] 에코 <상대>(<경로 lan|public|relay>): 왕복 Xms, 편도 Yms, 입→귀 Zms, 핑 Ams, 지터 버퍼 Bms — <판정>
```

예:

```
[실측 2026-11-12] 루프백 Focusrite USB ASIO (asio), 버퍼 64, 프레임 2.5ms 48000Hz/64: 왕복 6.10ms(σ 0.010ms), 드라이버 보고 5.90ms, est 5.17ms, 보정 +3.43ms — 정상
```

(위 숫자는 형식 예시이며 실측값이 아니다.)

함께 적을 것: Windows 버전, Focusrite 드라이버 버전, 앱 커밋, 케이블(라인 → 라인 / 헤드폰 → 라인 / 스피커 → 마이크).

## 7. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| "입출력 레이트가 달라" | 입력·출력 장치가 다른 레이트로 열렸다. 같은 인터페이스(ASIO 듀플렉스)로 잰다 |
| "입력 콜백이 돌지 않습니다" | 입력 장치가 다른 앱에 잡혀 있거나 분리됐다. 테스트를 껐다 켠다 |
| 루프백이 0~1ms | 직접 모니터가 켜져 있다 |
| 매번 신호 미검출 | 입력 채널이 연결한 단자와 다르다(Ch1/Ch2), 또는 INST/게인 최소 |
| 에코 "수락하지 않았습니다" | 상대가 30초 안에 허용하지 않았다, 또는 상대 앱이 이 기능 이전 버전이다 |
| 에코 "불안정"(흩어짐) | 회선 지터가 크다(튄 값 1개는 이미 빼고 본 결과). 잠시 뒤 다시 재고, 계속되면 지터 버퍼·손실 표시를 함께 적는다 |
| 에코 "불안정"(절반 이하) | 돌아온 클릭이 절반 이하 — 손실이 많다. 연결 상태(손실·은닉)를 적고 다시 잰다 |
