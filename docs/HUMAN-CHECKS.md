## 먼저 알아 둘 말

- **엔진**: 앱 안에서 소리를 받고 보내는 부분. "연주 참여하기"를 누르면 켜진다.
- **xrun**: 컴퓨터가 소리를 제때 만들지 못해 "틱" 하고 끊긴 횟수. 0이 목표다.
- **WASAPI 공유 / 독점**: Windows 기본 소리 방식. 공유는 다른 앱 소리와 함께 나오고, 독점은 이 앱만 장치를 써서 지연이 짧다(권장).
- **ASIO**: 오디오 인터페이스 회사가 주는 저지연 드라이버. 이 앱은 ASIO를 넣은 특별 빌드에서만 쓴다.
- **루프백 측정**: 인터페이스 출력을 케이블로 입력에 다시 꽂아 "삑" 소리가 돌아오는 시간을 재는 것. 컴퓨터 안의 지연을 잰다.
- **에코 측정**: 상대 PC가 내 클릭을 그대로 되돌려 보내게 해서 인터넷 포함 왕복 시간을 재는 것. 화면의 📏 버튼.
- **은닉**: 늦거나 사라진 소리 조각을 비슷한 소리로 메운 비율(%). 1.5% 이하가 목표다.
- **진단 zip**: 🩺 **진단 내보내기** 버튼이 만드는 파일. 최근 60분의 엔진 기록(1초 간격)과 로그가 들어 있다. 이메일·토큰·전체 IP는 가려진다.
- **릴레이**: 두 PC가 직접 연결되지 않을 때 소리를 대신 전달해 주는 서버.
- **NAT / 대칭형 NAT**: 공유기가 집 안 주소를 바깥 주소로 바꾸는 방식. LTE·회사망에 흔한 "대칭형"은 직접 연결이 잘 안 돼 릴레이가 필요하다.

## 공통 — 앱 실행 방법

아직 GitHub에 올라간 설치본이 없다(2026-11-20 기준 릴리스 0개). 그래서 모든 확인은 **개발 모드**로 실행한다.

```powershell
cd C:\dev\devdev\band-tauri
git switch develop
git pull
npm install
npm run dev:tauri          # 서버 + 앱을 함께 띄운다. 첫 빌드는 10~20분
```

> ⚠️ **개발 모드의 로컬 서버는 운영 DB(운영 Supabase)를 쓴다.** 개발용 DB가 아직 없다(P3-11, 미룸). 그래서:
> - 테스트 계정·`[TEST]` 방·채팅이 **운영 DB에 생긴다.** 끝나면 방을 지운다.
> - 로컬 서버는 운영 DB의 주 서버가 아니라서(#243) 전역 유지보수(모든 방 참가자 수 0 초기화, 결제 재조정·구독 만료·주문 정리·업로드/음원분리 파일 삭제 같은 정기 작업)와 입장·퇴장 때의 참가자 수 갱신을 하지 않는다. 그래서 테스트하는 동안 방 목록의 인원은 **0으로 보인다**(정상).
> - 서버 터미널에 `[DB] Supabase client initialized - participant sync disabled (not the primary server)`와 `[MAINT] 전역 유지보수(참가자 수 초기화·갱신, 정리·구독·주문 주기 작업) 건너뜀: …` 줄이 보여야 한다. 대신 `[MAINT] 전역 유지보수 실행 (…)`·`participant sync enabled`·`[DB] All room participants reset to 0`이 보이면(#243 이전 코드, 또는 `server\.env`의 `RUN_MAINTENANCE_JOBS=true|1`) 운영의 모든 방 참가자 수가 0이 되고 정리 작업이 운영 서버와 겹쳐 돈다 — 바로 끈다. `RUN_MAINTENANCE_JOBS`(`true|false|1|0`)는 로컬에서 켜지 않는다.
> - 2026-11-20부터 운영 서버가 같은 DB를 실제로 쓰고 있다. **누군가 운영에서 합주·관람 중이면 `npm run dev:tauri`를 켜지 않는다.**
> - 자세한 내용은 [TEST-SESSION.md](TEST-SESSION.md) 0절.
> - 서버를 띄우지 않을 PC(C의 PC B 등)는 `server\.env` 없이 `npm run tauri:dev`로 앱만 띄운다(TEST-SESSION 2.3).

- [TEST-SESSION.md](TEST-SESSION.md)는 2026-11-20 `develop` 기준으로 고쳐졌다(#242: 브랜치 `develop`, 컷오버 뒤 서버 상태, 화면 문구). 테스트는 지금도 PC A의 로컬 서버로 한다.
- 소리 확인에는 **유선 헤드폰**을 쓴다(스피커를 쓰면 상대 소리가 마이크로 다시 들어간다).
- 측정 결과는 측정 창의 **결과 복사** 또는 **텍스트로 저장**으로 남긴다. "백로그 기록:" 줄을 그대로 보내면 된다([MEASURE.md](MEASURE.md) 6절).

버전·시각·길이·백엔드·드라이버·프리셋·프레임·코어 배치·xrun 증가 시점), 피어별 표(bufferMs 중앙/p95/최대, 은닉 %(방식별), 손실 %, 손실 모양, 경로, RTT, 연결·첫 소리 ms), 연결 기록, GOAL 1·2절 판정표를 내고, 끝에 모든 zip을 합친 연결 성공률 집계(경로별 시도·성공·실패·중단·중앙 소요 ms)와 3절 판정을 Markdown으로 낸다(`--json`이면 같은 값을 JSON으로). 판정은 충족 / 미달 / 판정 불가(데이터 없음·세션이 기준보다 짧음·측정 구간이 GOAL 정의와 다름 — 비고에 이유)다. 충족은 근거가 완전할 때만 낸다: 은닉 %는 재생 프레임(`produced`) 분모(연결 중 무수신·리버퍼로 재생이 멈춘 시간은 은닉에도 분모에도 안 들어 "소리 없는 시간"으로 따로 보여 주고 — 기대치 비교 추정(구간마다 기대 재생 시간 − 실제 재생)이고, 진단 형식 3부터는 엔진이 잰 리버퍼 실측(`rebufferMs`)과 견줘 구간마다 **큰 쪽**을 쓴다: 실측은 처음 채우기(연결됐지만 소리 미도착)·워커/출력 스트림 정지를 세지 않아 실측만 쓰면 그 무음이 빠진다(#250 H2), 2-1은 은닉·손실을 하한(무음 제외)–상한(무음을 모두 은닉·손실로 봄, 피어마다 첫 연결 구간에서만 끝 오차 0.5초를 뺌 — 재연결 뒤 무음은 전부 넣음) 구간으로 가른다 — 충족은 은닉 상한 ≤ 1.5%·손실 하한 ≥ 1%일 때만, 미달은 은닉 하한 > 1.5%·손실 상한 ≤ 1%일 때만, 그 사이는 판정 불가), 1-4는 재생 중이 아닌 표본(bufferMs 0)을 띠 밖으로 세고, 3-3 첫 소리는 내 입장 → 피어 추가(`entryLeadMs`, 진단 형식 3부터 — **내가 시작할 때 이미 있던 연주자에만** 있다)로 "입장 후 첫 소리" = `entryLeadMs + firstAudioMs`를 가른다. 뒤에 들어온 연주자 항목은 기준이 "피어 추가"라 그 사람의 입장(누른 순간 → 장치 열기·STUN)을 담지 못해 참고값으로만 보이고 충족 근거가 아니다 — 그 사람의 입장은 **그 사람의 zip**에 있으니 참가자 모두의 zip을 받는다. 충족은 입장 값이 있는 항목이 하나 이상이고 모두 3초 이내일 때만이고, 옛 형식(입장 값 자체가 없음)이 섞이면 판정 불가, 피어 추가 후만으로 3초를 넘었거나 소리를 못 받았으면 미달이다(#250 M1). 3-2 분모에는 내보낼 때 아직 연결 중인 시도가 "미완"으로 들고(모두 성공해도 98% 아래일 때만 미달), 시도 수는 기록 기준이라 한 합주의 양쪽 zip을 함께 주면 98% 문턱은 겹치는 기록 중 시도가 가장 많은 사람 것만 센다(같은 사람이 같은 세션을 여러 번 내보낸 zip은 **넣는 순서와 상관없이** 하나로 합쳐 — 시간이 겹치는 것끼리 사슬로 — 연결 기록을 한 번만 센다, #250 H1'). 3-1(콘형 NAT 쌍 직접 100%)은 진단 형식 3부터 세션 첫 줄 `nat`(두 STUN 서버가 본 공인 주소가 같으면 콘형)과 `selfPeer`(내보낸 사람의 가명 — 상대 zip의 피어 가명과 같은 값)로 가른다: 같은 시간에 **서로를 피어로 본 두 사람의 zip이 모두 있고** 둘 다 `independent`·`open`인 쌍만 콘형 쌍이고(같은 PC가 두 번 내보낸 zip은 한 사람이라 쌍이 아니다), 실제 시도 하한(쌍마다 양쪽 기록 중 많은 쪽 — 이를 쌍끼리 더한 값, 쌍마다 3회가 아니다)이 **3회 이상**이고 모두 직접일 때만 충족이다(#250 H1·M2 — 연결 한 번으로 "100%"를 내지 않는다). 한쪽 zip만이거나 `selfPeer`가 없는 zip(이 PR 이전)이면 판정 불가. 청감과 유선/Wi-Fi는 진단에 없으니 TEST-SESSION 8절 기록표 값으로 채운다. GOAL 1-4(±3ms 1분)·2-1(은닉 %)은 이 도구와 같은 PR(#246)부터 타임라인에 기록되는 `targetMs`·`produced`가 필요해, 그 전 빌드의 zip은 판정 불가로 나온다. 기준값은 `crates/band-engine/src/diag/report/mod.rs`의 `goal` 한 곳(GOAL.md 절 번호 주석).
